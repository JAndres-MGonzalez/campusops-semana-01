## Predicción

Antes del experimento se registró que importar infraestructura desde la pantalla de lista debía provocar un error `ui -> infrastructure`. Al retirar ese cambio, el detector y TypeScript debían pasar. La predicción está en `reports/week-02/boundary-plan.json`.

## Falla y corrección

El 14 de septiembre de 2026 se agregó temporalmente a `src/ui/screens/IncidentListScreen.tsx`:

```ts
import type { InMemoryIncidentRepository } from '../../infrastructure/incidents/in-memory-incident-repository';
const _forbidden: typeof InMemoryIncidentRepository | null = null;
```

La ruta `../../` llega a `src/infrastructure` desde la carpeta de la pantalla.

Al ejecutar `node tools/check-boundaries.mjs`, el síntoma fue el mensaje de violación de límites y el código 1. La causa fue el import directo de UI hacia infraestructura, contrario al ADR. Se retiraron las dos líneas y se restauraron los bytes originales. El mismo comando devolvió código 0 y confirmó 13 dependencias internas permitidas. `npm run typecheck` también terminó con código 0.

La pantalla debe pedir los datos mediante el caso de uso. Si usa directamente el adaptador en memoria, queda ligada a esa forma de guardar los datos y habría que cambiarla al usar otro proveedor. Al quitar ese import, la pantalla vuelve a respetar la separación acordada.

El cambio temporal está en `reports/week-02/logs/controlled-import.patch`. Las salidas están en `boundaries-failure.log`, `boundaries-corrected.log` y `typecheck-corrected.log`, dentro de `reports/week-02/logs/`. `reports/week-02/restoration.json` contiene los hashes antes y después; código, pruebas públicas, evaluador y documentos de arquitectura quedaron idénticos.
