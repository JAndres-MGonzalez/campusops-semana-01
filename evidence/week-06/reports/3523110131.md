## Predicción

Las solicitudes simultáneas deben compartir una renovación. Cada solicitud debe reintentarse una sola vez y una renovación pendiente no debe recuperar la sesión después de cerrarla.

## Comprobación

`npm.cmd test -- --ci --runInBand evidence/week-06/concurrency.test.ts`: ocho casos, cuatro aprobados y cuatro fallidos. Se utiliza el módulo de sesión de la rama de Kevin, sin modificarlo. El reloj se controla en la prueba y el backend se ejecuta en una dirección local.

Resultados fallidos:

- Una solicitud repetida se registra tres veces en `retriedRequestIds`, en lugar de una.
- Durante una renovación compartida, el estado observado es `expirado`, aunque la renovación sigue pendiente.
- Si se cierra sesión durante la renovación, su respuesta posterior vuelve a guardar la sesión y deja el estado `autenticado`.
- El backend real responde al login con HTTP 200, pero el manager rechaza su formato. El servidor devuelve `accessToken`, `refreshToken` y `expiresIn`; el manager espera `token`, `generation` y `expiresInMs`.

`npm.cmd test -- --ci --runInBand course-tests/public/week-06.test.ts src/infrastructure/session/session.test.ts`: dos suites y siete casos aprobados. Esos casos no cubren los cuatro fallos anteriores.

La instalación limpia, `make PYTHON=python feedback`, `make PYTHON=python verify-week-06` y `npm.cmd run check:architecture` terminaron con código 0. `make PYTHON=python public-test-week-06` terminó con código 2 por ausencia de `auth-tests.json`, `engineering.json` e `individual.json`. Los comandos, códigos de salida y resultados están guardados en los logs.

## Explicación

Compartir la renovación evita pedir una sesión nueva por cada solicitud. También hay que evitar reintentar la misma solicitud varias veces. Al cerrar sesión, una respuesta que llegue tarde debe descartarse para que el usuario no vuelva a quedar conectado.

## Limitación

Los resultados todavía no acreditan el ciclo de sesión completo. La app sigue usando el token sintético fijo del cliente de incidencias y no conecta el manager de sesión. Las pruebas usan almacenamiento en memoria; no comprueban el almacenamiento seguro en un dispositivo físico.
